# 当前功能与性能评估

评估日期：2026-10-21。对象：`codex/winui3-modernization` 中的 Files.WinUI，
不是仓库默认分支中的旧 UWP 应用。

## 判断

当前版本适合作为迁移预览和受控试用版本。常用文件浏览与基础写入路径已经实现，
复制与导航有核心回归覆盖；完整日常使用仍需要补齐文件操作反馈与 Windows 交互验收。
不能仅凭构建成功或界面截图认定它已能替代 Windows 文件资源管理器。

## 功能与证据

| 功能 | 当前行为 | 验证程度 |
| --- | --- | --- |
| 目录、磁盘与路径浏览 | 侧栏入口、路径输入、后退/前进/上一级、刷新；目录优先、名称排序 | 核心枚举与导航回归；实际 x64 启动和路径导航见本次运行记录 |
| 名称筛选 | 只筛选当前目录，忽略大小写；不是递归搜索 | 核心表达式基准；小目录实际界面筛选与恢复检查 |
| 打开普通文件 | 通过 Windows 默认关联程序打开 | 已实现；本次未逐类启动外部程序验收 |
| 新建与重命名 | 校验 Windows 文件名及保留设备名，拒绝覆盖 | 核心回归；尚未逐项自动操作 Windows 输入对话框 |
| 复制/粘贴 | 系统文件剪贴板；逐个根项目暂存、复制完成后提交；冲突拒绝 | 核心回归与复制后内容校验；外部应用剪贴板仍需人工验收 |
| 回收站 | 用户确认后交给 Windows；不支持回收站的位置保留系统确认 | 已实现；本次没有验证删除后还原、网络盘与 U 盘 |
| 外观和键盘 | 系统/浅色/深色，隐藏项开关，多选；Ctrl+L、F5、Alt+方向键、Enter、F2、Delete | 实际默认主题截图；高 DPI、高对比度、屏幕阅读器仍未验收 |
| 部署 | 自包含目录；x64、ARM64 发布 | 两种架构均构建；仅 x64 实际运行；未验证纯净 Windows 客户机 |
| 待补功能 | 剪切/移动、覆盖决策、操作进度和取消、缩略图、标签页、拖放、预览、递归搜索、排序界面 | 未实现；主题与隐藏项设置也尚未持久保存 |

核心回归：Linux 36/36、Windows 34/34。Windows 两个符号链接用例因权限跳过，
不应算作通过。核心测试不替代剪贴板、Windows Shell、实际介质、辅助功能验收。

## 性能测量

本次增加可复跑的 `tests/Files.Performance` 和 `scripts/evaluate-winui.ps1`。
后者使用 UI Automation 操作真实应用，再截取 Windows 桌面上应用窗口的像素。
演示目录为测试时生成的 8 个项目，不读取用户电脑上的私人文件。

以下为本次测量结果。原始 JSON 保留每次样本、
操作系统、运行时、逻辑处理器数、来源提交和方法说明。

来源分支提交：`407a06e52d16572c8ab7b3ba82c35fb9bd348794`。
CI 实际检出的 PR 合并引用（两份 JSON 的 `SourceCommit`）：`70f75c8b81f9f5c209e52850a42fb656873a15a8`。
[验证运行 #18](https://github.com/olisuvan/files-uwp/actions/runs/39544883657)：四项任务全部通过。

环境：Windows Server 2025 / build 26100，x64，4 个逻辑处理器，约 16 GiB 可用内存，
.NET 10.0.13，runner image `20261007.264.1`；Release，自包含应用。

| 项目 | 中位数 | 本轮最小—最大 | 样本数 |
| --- | ---: | ---: | ---: |
| 启动到窗口出现 | 341.4 ms | 330.7–370.0 ms | 3 |
| 启动到初始目录路径提交 | 556.1 ms | 545.8–1679.0 ms | 3 |
| 8 项目录导航观察 | 71.3 ms | 65.5–165.4 ms | 3 |
| 8 项目录筛选观察 | 131.5 ms | 130.2–133.3 ms | 3 |
| 静置工作集 | 143.6 MiB | 141.8–148.6 MiB | 3 |
| 静置私有字节 | 59.9 MiB | 59.0–60.3 MiB | 3 |
| 读取元数据并排序：500 项 | 0.65 ms | 0.58–0.76 ms | 5 |
| 读取元数据并排序：5,000 项 | 5.74 ms | 4.70–14.69 ms | 5 |
| 读取元数据并排序：20,000 项 | 47.53 ms | 26.91–433.54 ms | 5 |
| 20,000 项全匹配筛选表达式（不含 UI） | 0.44 ms | 0.43–0.54 ms | 5 |
| 20,000 项零匹配筛选表达式（不含 UI） | 0.18 ms | 0.17–0.18 ms | 5 |
| 复制 128 MiB 单文件（缓存条件） | 103.46 ms | 101.64–107.48 ms | 3 |
| 复制 1,000 个 1 KiB 文件 | 547.18 ms | 428.87–893.15 ms | 3 |

首轮初始目录路径提交为 1,679 ms，后两轮约 546–556 ms。它们都发生在先前启动冒烟检查之后，
因此不能把首轮称作操作系统冷启动。20,000 项读取的最大样本 434 ms，明显高于 48 ms 中位数；
本轮不足以归因或估计尾部延迟，需要更多端到端样本。

小目录路径导航、筛选为单项、清空筛选恢复文件夹、窗口正常关闭，均由真实 UI 自动化在三次运行中检查。
本轮没有发现核心枚举或复制的功能失败；大目录的控件绑定、滚动、输入响应与峰值内存仍未测量。
单看 20,000 项筛选表达式约 0.44 ms，不能断定扫描本身是主要瓶颈；优化应先测重绑与布局的实际成本。

分发 ZIP：x64 为 95,538,146 字节（91.1 MiB），ARM64 为 92,777,031 字节（88.5 MiB）。
这是压缩分发体积，不能当作进程内存或解压后的磁盘占用。

原始样本：[核心性能 JSON](evaluation/core-performance.json)、[界面性能 JSON](evaluation/ui-performance.json)。
实际运行截图位于该运行的 `Files-Windows-evaluation` 产物中，并已单独交付。

解释范围：

- 这是 Windows CI 虚拟机的测试结果，不是用户电脑的结果，也没有与旧版或 Explorer 做对照。
- 启动为同一虚拟机上的三次顺序启动；没有清空操作系统缓存。窗口出现和初始路径提交
  分开记录；后者不是严格的首帧渲染时间。UI 观察含 100ms 轮询和 UIA 调用开销。
- 目录基准包括后台枚举、文件元数据读取和排序，不包括绑定、布局和绘制。
  新建测试文件后的首次读取也不是真正冷盘读取。
  测试目录分别含 500、5,000、20,000 个 1 字节文件，名称格式固定，不含嵌套目录。
- 筛选微基准使用与界面相同的 LINQ 表达式，但不包含列表替换、选择变化、布局与绘制。
  每个样本重复 100 次后求单次平均，再对 5 个样本取中位数。
- 复制为本机缓存条件下的逻辑复制，包含暂存与提交；内容校验/哈希不计时。
  `FlushAsync` 不保证数据已物理落盘，不能将该速率当作硬盘、U 盘或网络盘带宽。
- 工作集与私有字节含义不同；此处是操作后静置 2 秒的快照，未做持续增长或泄漏测试。
  三到五个样本只用于初步评估，不足以计算可信的 P95/P99 或稳定性能保证。

## 按收益排序的改进

| 优先级 | 发现与用户影响 | 建议 | 验收方式 |
| --- | --- | --- | --- |
| P1 | `DeleteSelected` 在界面 STA 线程同步调用 `SHFileOperationW`。慢介质或大量项目会阻塞窗口消息处理。 | 以正确的 STA/COM 模型隔离 Shell 操作，评估 `IFileOperation` 和进度反馈；保留窗口归属及取消语义，不能直接丢进普通 MTA `Task.Run`。 | 测试多文件、慢盘、取消和不支持回收站的位置，记录操作期间界面响应与最终内容。 |
| P1 | 复制虽然在后台运行，但界面只进入忙状态，没有字节进度、剩余量或取消按钮。 | 增加操作进度与显式取消；说明多根项目可能部分成功，保留现有不覆盖与暂存提交规则。 | 大文件/小文件树复制，执行中取消，确认源和已有目标不变、临时项可解释。 |
| P2 | `ReadAsync` 必须枚举全部项目并排序后才返回，时间与内存随项目数增长；虚拟化只减少控件数量。 | 在保持导航版本保护的前提下评估分批展示、增量排序和可取消的读取；先以用户常见目录规模设目标。 | 5千、2万、10万项目的端到端可交互时间、峰值内存、滚动和快速切换。 |
| P2 | 每次筛选都在 UI 线程扫描全量数组并重新设置 `ItemsSource`。微基准快也不能保证大目录输入/滚动流畅。 | 增加短延迟合并输入，必要时移到后台并保留最后请求；减少无效刷新，验证选择与滚动位置。 | 连续输入/清空、全匹配和零匹配，并记录 UI 帧与输入延迟。 |
| P2 | `OnLoaded` 等待磁盘发现完成后才导航到个人目录；断开的网络驱动器可能拖慢首屏。 | 首目录加载与侧栏磁盘发现解耦，磁盘入口异步补齐。 | 挂载不可达网络盘，确认本地首屏不被其阻塞。 |
| P2 | 自包含部署附带 .NET 与 WinUI 运行库，分发体积较大，尚无安装和自动更新。 | 在可复现发布基础上评估 MSIX/安装器和更新渠道；裁剪或 NativeAOT 应先做 WinRT/XAML 兼容验证。 | 纯净 Windows 安装/启动/卸载、不同架构、升级回滚与包大小。 |

复制当前仅保留常规文件数据流，不保留完整 ACL、备用数据流等；不适合作为备份工具。
拒绝符号链接/目录联接是明确的产品限制，不代表对恶意并发路径替换提供安全隔离。

## 复跑

```powershell
dotnet run --project tests/Files.Core.Tests -c Release
dotnet run --project tests/Files.Performance -c Release -- artifacts/evaluation/core-performance.json
dotnet publish src/Files.WinUI/Files.WinUI.csproj -c Release -p:Platform=x64 -r win-x64 -o artifacts/win-x64
powershell -NoProfile -STA -File scripts/evaluate-winui.ps1 -PublishDirectory artifacts/win-x64 -OutputDirectory artifacts/evaluation
```

截图采集需要有可见桌面的 Windows 会话。测量在 Release 配置下执行；创建和清理测试数据不计时。
CI 产物 `Files-Windows-evaluation` 包含 PNG 截图和两份测量 JSON。
